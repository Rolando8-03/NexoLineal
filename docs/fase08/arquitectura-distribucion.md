# Decisiones de distribución 0.8.0

La aritmética y los contratos permanecen en `packages/core`. Vite construye una interfaz por destino: web incorpora Pyodide; Windows y Android incorporan sus recursos visuales y delegan a Python nativo. `prepare-distribution.mjs` agrega versión, SHA del código, hash del manifiesto Python y un identificador de bytes de cada build. El identificador difiere entre destinos porque sus recursos difieren; la versión, el SHA de fuente y el núcleo deben coincidir.

En web, el Service Worker se registra al solicitar la descarga offline. Su instalación verifica todos los recursos estáticos por SHA-256 antes de activar la nueva caché. No ejecuta `skipWaiting`. Los clientes abiertos continúan con su versión hasta cerrarse; la activación elimina cachés anteriores, conservando candidatos posteriores. Los proyectos no se guardan en Cache Storage: IndexedDB confirma una transacción antes del aviso de guardado. La migración desde localStorage conserva el documento anterior.

El adaptador Windows espera a que estén disponibles todos los métodos requeridos del puente; la mera existencia de `pywebview.api` no acredita que haya terminado su registro. La espera devuelve un contenedor para no asimilar accidentalmente proxies con una propiedad `then`. La regresión reproduce un objeto vacío y un registro parcial antes de permitir el cálculo.

En Windows, PyInstaller `--noconsole --onefile` incluye Python, módulos y `ui`. Inno Setup instala por usuario, con un AppId fijo para actualizaciones. El runtime WebView2 completo procede del distribuidor oficial de Microsoft y se verifica antes de empaquetar; el instalador consulta sus registros x86/x64 por equipo y usuario. Si falta, ejecuta el prerrequisito y verifica su presencia antes de continuar. Un fallo informa el código y no borra los proyectos. El desinstalador no elimina datos ni WebView2 compartido.

SQLite guarda el documento portable completo en una fila versionada, con transacciones y confirmación antes de responder al puente. Windows cierra las conexiones explícitamente; Android usa SQLiteOpenHelper y transacciones. La migración nativa valida el JSON previo, lo inserta sin sustituir una fila ya existente y conserva el archivo. Una base corrupta o una versión de esquema desconocida no se borra automáticamente. La exportación JSON sigue siendo el mecanismo portable entre destinos.

Android separa debug y release no depurable. Gradle toma la firma únicamente de variables de entorno, con archivo fuera del checkout. Si CI carece de secretos del propietario, usa una clave efímera para verificar la compilación release y etiqueta el artefacto como prueba. El hash y la huella de esa prueba no acreditan la cadena de actualizaciones del propietario. El selector nativo de exportación de documentos mantiene su ruta de prueba limitada a builds debug; release usa el selector Android real.

El frontend solicita guardado al pasar a segundo plano. Atrás cierra el diálogo, después el menú, vuelve al inicio desde otra sección y, desde inicio, solicita guardado antes de mandar la actividad al fondo. La tecla del teclado en pantalla se gestiona primero por Android. La instrumentación ejercita estos recorridos; la comprobación del teclado físico real queda en B54.

Los workflows anteriores permanecen como regresión: 136 contratos, integridad del núcleo, cancelación, recuperación, experiencia y documentos. El workflow de distribución agrega instalación, ciclo de vida release, persistencia cruzada, medidas e inventarios. GitHub Pages publica únicamente `apps/frontend/dist`, nunca la raíz completa del repositorio. La fase 09 conserva la publicación estable y validación final; este paquete técnico no adelanta ese cierre.
